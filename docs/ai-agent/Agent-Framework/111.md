你的后台任务还在一个“黑盒”里面运行吗？

任务什么时候开始、什么时候结束、当前是否正在运行、执行了多长时间，这些信息如果只能通过日志查看，排查起来还是比较麻烦。

那么，如何让后台定时任务也能在页面上实现可观察性？

这一节我们使用 **ASP.NET Core + Quartz.AspNetCore + SignalR**，来实现后台定时任务运行状态的可视化。

## 为什么使用 SignalR，而不是客户端轮询？

轮询需要客户端每隔一段时间主动向服务器发送请求，因此任务状态的更新会存在一定延迟。

如果轮询间隔设置得太短，会产生大量无效请求，增加服务器压力；如果间隔设置得太长，又不能及时展示任务的最新状态。

SignalR 通过长连接，在任务开始或结束时由服务端主动向客户端推送状态。这样实时性更好，平时也不需要客户端反复发送请求。

虽然 SignalR 的接入成本会稍微高一点，但它更适合这种事件驱动的场景，比如：

- 任务开始时，在页面新增一条执行记录
- 任务结束时，更新同一条记录的结束时间和执行状态


## Quartz 定时任务状态

Quartz 本身提供了任务调度和状态管理能力，比如任务的运行、暂停、恢复等基本状态。

我们可以利用这些状态，在页面上展示当前定时任务的运行情况，让后台任务不再完全处于“黑盒”状态。



## 跟踪任务执行过程

除了 Quartz 本身的任务状态，我们还可以进一步记录每一次任务的实际执行过程。

任务开始执行时，通过 SignalR 向客户端推送**开始时间**。

任务执行结束后，再通过 SignalR 向客户端推送**结束时间**和执行结果。

图

这样页面就可以完整记录一次任务的执行过程，并计算出本次任务实际执行了多长时间。

当然，除了开始时间、结束时间和执行状态之外，还可以根据实际业务需要，把任务执行结果、处理的数据量、异常信息等一起推送到页面进行展示。
